# Phase 0 报告：DeepSeek-OCR 稳定性实验

**日期**: 2026-08-30
**实验对象**: `10.1109_tii.2020.2999571.pdf`（11 页，IEEE TII 2020，FDIA 检测）
**方法**: 同一 PDF 用 DeepSeek-OCR（经 new-api 网关 :3000，模型 `deepseek-ai/DeepSeek-OCR`）跑两次，输出到 `labs/run1` 与 `labs/run2`，三层 diff。

## 实验数据

| 层级 | 指标 | 结果 |
|---|---|---|
| L1 章节结构（`##`/`###` 序列） | 标题数 run1/run2 | 14 / 14 |
| L1 章节结构 | 序列完全一致 | **是**（唯一差异：`FDIAIS` vs `FDIA's`，OCR 词边界误读，非结构变化） |
| L2 行指纹（前 64 字符，按行序对齐） | 对齐匹配率 | **127/140 = 90.7%** |
| L3 全行内容地址（sha1-8，集合无关） | run1 行在 run2 中存在 | **133/141 = 94.3%** |
| L3 全行内容地址 | run2 行在 run1 中存在 | 133/140 = 95.0% |
| 近似匹配（difflib ratio） | 不精确匹配的 18 行分布 | ratio=1.0（11，纯重排）、0.95–1.0（7，微漂移）、<0.95（**0**） |

## 真正的内容漂移（仅 7/141 ≈ 5%，且全部 ratio ≥ 0.95）

全部集中在非正文元素，无一段实质性内容变化：

1. LaTeX 宏名：`\mathrm{argmin}` → `\operatorname{argmin}`
2. 表格单元格数：`colspan="12"` → `colspan="11"`（真实提取差异）
3. OCR 词边界：`FDIAIS` → `FDIA's` / `FDIA`（复数与撇号）
4. 标点空格：`Fig. 6.` → `Fig.6.`
5. 作者简介附近图片放置顺序：`p9_0.jpg`/`p10_0.jpg` 与正文行的相对顺序调换（**纯重排**，内容不变）

**结论：正文段落（承载 claim 的部分）近 100% 稳定；漂移 < 5%，且无一段 ratio < 0.95。**

## 关键发现：行序不稳，内容稳

- 按行序对齐匹配 = 90.7%；按内容集合匹配 = 94.3%。**差出的 ~4% 全是重排**（作者简介区的图片/文字相对顺序）。
- 这直接证明：**基于内容的锚点（content-addressed）比基于行序/段序的锚点更稳**——内容地址恢复了重排丢失的 4%。

## 对照综合简报的决策表 → 命中第 1 行

| 决策表结果 | 锚点方案 | 存储形态 | 粒度 |
|---|---|---|---|
| **章节结构稳定；段落文本漂移 < 5%（实测命中）** | **内容哈希（全段落归一化 sha1-8）** | **SQLite 锚点表** | **段落/行级** |

## 锚点方案（实验修正后的最终形态）

实验给出了比任何单一视角都精确的方案——三层结构，全是确定性、零 LLM：

1. **主锚点：全段落内容哈希**（NFKC 归一化 + 空白折叠后 sha1-8）。对 ~94% 的行永久稳定。
2. **回退：模糊重匹配**（difflib SequenceMatcher ratio ≥ 0.9，对当前 OCR 段落集合）。对 ~5% 漂移行自动重绑——确定性，无 LLM。匹配 ≥0.9 → 重绑 + 标记 `relocated`；<0.9 → 标记 `broken`。
3. **父上下文：章节路径**（`##`/`###` 标题链，实测 100% 稳定）随每个锚点存储，用于查询时消歧与"哪一节"回答。**章节是上下文轴，不是锚点本身**——这拒绝了迁移专家的"section 锚点"方案（太粗，丢失用户需要的段落精度），但保留章节为二级轴。

**这同时验证了**：架构师的"内容寻址锚点"赌注（对）、扩展性工程师的"SQLite 查询底座"赌注（对）、迁移专家的"章节结构稳定"观察（对，但作上下文而非锚点）。三个视角的分歧被一个 10 分钟实验一次性收敛。

## 对"是否构建"的诚实标注（同行评审的盲点）

当前 test bed 语料仅 84 篇。在 <500 篇时，"JSON 文件夹 + agent 直接读文件"确实够用，markdown+grep 也够。本实验验证的是**锚点 schema 的可行性**，不是"必须现在建知识层"。是否进入 Phase 1 的构建决策，应由 Phase 0.5 的引文命中率 + 用户的真实跨项目查询需求共同决定，而非本实验单独决定。
